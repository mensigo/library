## Интро

`classmethod` и `staticmethod` нужны, когда метод логически относится к самому классу, а не к конкретному его объекту.

Оба декоратора помогают поддерживать API аккуратным: полезные функции остаются внутри класса и при этом не выглядят как обычные instance-методы.


## Моменты

### 1. Когда использовать classmethod

`classmethod` стоит выбирать, когда методу нужен доступ к самому классу (`cls`):

- Когда делаем альтернативный конструктор (например, создание объекта из строки, словаря, json)
- Когда метод должен учитывать наследование и создавать именно текущий подкласс
- Когда работаем с данными/настройками на уровне класса, а не экземпляра

**Почему это выгодно:**
- Снижается дублирование логики создания объектов
- Конструкторы становятся более читабельными (`User.from_dict(...)`, `Config.from_env(...)`)
- Код лучше расширяется при наследовании, потому что используется `cls`, а не жестко прописанный класс


### 2. Когда использовать staticmethod

`staticmethod` подходит, когда метод вообще не зависит ни от состояния объекта (`self`), ни от класса (`cls`):

- Когда это утилитарная функция, которая тематически относится к классу
- Когда нужно сгруппировать вспомогательную логику рядом с основным кодом класса
- Когда хотим явно показать: этот метод ничего не читает и не меняет в объекте/классе

**Почему это полезно:**
- Класс остается структурированным: вспомогательные функции лежат рядом
- Повышается читаемость API: видно, что это helper, а не часть состояния
- Проще поддерживать код благодаря более четким границам ответственности методов


### 3. Кратко

- Нужен доступ к классу / создание экземпляров через `cls` -> `classmethod`
- Нужна просто вспомогательная функция без `self` и `cls` -> `staticmethod`

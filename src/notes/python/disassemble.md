## Интро

Python не исполняет исходный код напрямую. Сначала компилятор превращает его в список простых инструкций - байт-код, - а потом эти инструкции одну за другой выполняет виртуальная машина:

<div class="flow">
исходный код <i>→</i> компиляция <i>→</i> <b>байт-код</b> <i>→</i> виртуальная машина <i>→</i> результат
</div>

Модуль `dis` показывает именно байт-код - то есть то, что получилось после компиляции и до выполнения.


## Структура вывода dis.dis()

{% include "figures/dis-columns.njk" %}

Номер строки исходного кода печатается только у первой инструкции этой строки, остальные идут под ней с пустой колонкой. Смещение - адрес инструкции в байтах от начала функции: каждая занимает минимум два байта, и именно на эти адреса ссылаются переходы. У части инструкций аргумента нет вовсе - тогда пусты и последние две колонки.


Теперь целиком, на живом примере:

```python multiply.py
import dis

def multiply(x, y):
    return x * y

dis.dis(multiply)
```

::: out
```
  3           0 RESUME                   0

  4           2 LOAD_FAST                0 (x)
              4 LOAD_FAST                1 (y)
              6 BINARY_OP                5 (*)
             10 RETURN_VALUE
```
:::

`RESUME` - служебная инструкция в начале функции, привязанная к строке с `def`. Дальше две `LOAD_FAST` кладут на стек `x` и `y`, `BINARY_OP` с кодом `5` снимает оба значения и кладет обратно произведение, а `RETURN_VALUE` возвращает то, что осталось на вершине. Смещение прыгает с 6 сразу на 10, потому что за `BINARY_OP` идет скрытая ячейка кэша - `dis` показывает ее только с `show_caches=True`.

::: note Версии
Весь вывод получен на CPython 3.12. На других версиях могут отличаться названия и набор инструкций, их аргументы и смещения.
:::


## Основные инструкции

**Загрузка на стек**

| Инструкция | Что делает |
| --- | --- |
| `LOAD_FAST i` | Кладет на стек локальную переменную номер `i` |
| `LOAD_GLOBAL i` | Кладет на стек глобальную переменную или встроенную функцию по имени из таблицы имен |
| `LOAD_CONST i` | Кладет на стек константу номер `i`: число, строку, `None` |

**Работа со стеком**

| Инструкция | Что делает |
| --- | --- |
| `STORE_FAST i` | Снимает вершину стека и записывает в локальную переменную номер `i` |
| `POP_TOP` | Снимает вершину стека и выбрасывает ее |

**Арифметика**

| Инструкция | Что делает |
| --- | --- |
| `BINARY_OP op` | Снимает два значения и кладет результат операции. Сама операция задана кодом: `+` (0), `-` (10), `*` (5), `/` (11) |

**Управление потоком**

| Инструкция | Что делает |
| --- | --- |
| `POP_JUMP_IF_FALSE d` | Снимает вершину стека и, если она ложна, прыгает вперед. Так устроены `if` и выход из цикла |
| `JUMP_FORWARD d` / `JUMP_BACKWARD d` | Безусловный прыжок вперед или назад - например, в начало цикла |
| `RETURN_VALUE` | Возвращает вершину стека из функции |
| `RETURN_CONST i` | Возвращает константу номер `i` без отдельной загрузки. Появилась в 3.12 |


## Стек в основе

Виртуальная машина Python - **стековая**. Никаких регистров и переменных на ее уровне нет, есть только стопка значений. Почти каждая инструкция либо кладет что-то на вершину стопки, либо снимает оттуда несколько штук, что-то с ними делает и кладет результат обратно.

::: note Аналогия
Стек - это стопка тарелок. Добавить и забрать можно только сверху. `BINARY_ADD` снимает две верхние тарелки и кладет на их место одну - сумму снятых.
:::

Стековая машина - решение CPython, а не требование языка. Спецификация Python описывает, что делает код, но не то, как его исполнять. Другие реализации устроены по-своему:

- **PyPy** - начинает с похожего байт-кода, но горячие участки JIT-компилятор превращает в машинный код
- **Jython** и **IronPython** - компилируют Python в байт-код JVM и CIL .NET: тоже стековые, но это чужие виртуальные машины со своими инструкциями
- **MicroPython** - собственный компактный байт-код

Поэтому все, что показывает `dis`, относится к CPython конкретной версии. Модель «кладем на стек, снимаем, кладем результат» полезна, чтобы понимать порядок вычислений, но опираться на нее в коде в общем случае не стоит.


## Моменты

### 1. Вывод dis.dis() для разных объектов

Можно посмотреть раскладку не только для функции:

```python
import dis

dis.dis(my_function)     # Для функции
dis.dis(MyClass.method)  # Для метода
dis.dis(MyClass)         # Для класса
dis.dis(sys)             # Для модуля
dis.dis("x = 1 + 2")     # Для строки с кодом
```

Например, метод класса:

```python method.py
import dis

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def norm(self):
        return abs(self.x) + abs(self.y)

dis.dis(Point.norm)
```

::: out
```
  8           0 RESUME                   0

  9           2 LOAD_GLOBAL              1 (NULL + abs)
             12 LOAD_FAST                0 (self)
             14 LOAD_ATTR                2 (x)
             34 CALL                     1
             42 LOAD_GLOBAL              1 (NULL + abs)
             52 LOAD_FAST                0 (self)
             54 LOAD_ATTR                4 (y)
             74 CALL                     1
             82 BINARY_OP                0 (+)
             86 RETURN_VALUE
```
:::

Метод - обычная функция: `self` в ней просто локальная переменная номер `0`. Встроенная `abs` ищется через `LOAD_GLOBAL`, атрибуты читает `LOAD_ATTR`, а `CALL` вызывает функцию с одним аргументом.

Аргументы `LOAD_GLOBAL` и `LOAD_ATTR` - это индекс в таблице имен `('abs', 'x', 'y')`, сдвинутый на бит влево, а младший бит хранит служебный флаг: поэтому `abs` (индекс 0) превращается в `1`, `x` получает `2`, а `y` - `4`.

### 2. Сравнение кода через dis

Поможет при выборе оптимального варианта:

```python
import dis

# Вариант 1: через list comprehension
dis.dis("[x * 2 for x in range(10)]")

# Вариант 2: через цикл
dis.dis("""
result = []
for x in range(10):
    result.append(x * 2)
""")
```

List comprehension обычно оптимален.


### 3. Оптимизация при компиляции

Python вычисляет некоторые константные выражения на этапе компиляции:

```python
dis.dis("1 + 2")  # Покажет LOAD_CONST с уже посчитанным 3
```


### 4. Байт-код сохраняется в .pyc-файлы

Когда модуль импортируется, Python кэширует его байт-код в `.pyc`-файле рядом с исходником:

```
__pycache__/
    my_module.cpython-312.pyc
```

При следующем импорте компиляция пропускается: Python сверяет время изменения и размер исходника с записанными в заголовке `.pyc` и, если они совпадают, берет готовый байт-код. Быстрее становится только загрузка модуля - сам код выполняется с той же скоростью.

Скрипт, запущенный напрямую (`python main.py`), не кэшируется: он компилируется заново при каждом запуске.

Прочитать байт-код из кэша можно так - после 16-байтового заголовка в файле лежит сериализованный объект кода:

```python pyc.py
import dis, importlib.util, marshal

path = importlib.util.cache_from_source('my_module.py')
with open(path, 'rb') as f:
    f.read(16)              # заголовок: magic, флаги, mtime/хэш, размер
    code = marshal.load(f)
dis.dis(code)
```

`cache_from_source` надежнее, чем путь вручную: кэш может лежать не в `__pycache__`, если задан `PYTHONPYCACHEPREFIX`.


### 5. Просмотр dis на уровне кода - dis.get_instructions()

Вместо печати, можно получить инструкции как объекты (на уровне кода):

```python instructions.py
import dis

def add(a, b):
    return a + b

for instruction in dis.get_instructions(add):
    print(f"{instruction.offset}: {instruction.opname} {instruction.arg}")
```

::: out
```
0: RESUME 0
2: LOAD_FAST 0
4: LOAD_FAST 1
6: BINARY_OP 0
10: RETURN_VALUE None
```
:::

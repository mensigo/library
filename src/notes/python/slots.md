## Интро

`__slots__` в Python — это механизм, позволяющий клепать более легковесные объекты классов за счет ограничения их структуры. 


## Идея

По умолчанию каждый* объект хранит атрибуты в `__dict__` (обычном словаре).

Пример:
```python
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

User("Alice", 20).__dict__  # {'name': 'Alice', 'age': 20}
```

Это позволяет динамически добавлять новые атрибуты и удобно сериализовать/инспектировать объекты, но не всегда экономно по памяти. Проблема возникает, когда таких объектов очень много: накладные расходы `__dict__` заметно увеличивают потребление памяти (это же хэшмапы...).

В качестве решения Python позволяет прописать в определении класса атрибут `__slots__` со значением - коллекцией имен (обычно кортеж/список**):

```python
class User:
    __slots__ = ("name", "age")

    def __init__(self, name, age):
        self.name = name
        self.age = age
```

Хотя доступ к полям работает как прежде (`user.name`, `user.age`), способ их хранения в памяти меняется.

На практике это:
- уменьшает память на экземпляр (особенно заметно при большом количестве объектов)
- немного ускоряет*** доступ к атрибутам в ряде сценариев


## Моменты

### 1. Новые атрибуты

Нельзя свободно добавлять новые атрибуты, если они не объявлены в `__slots__` (будет исключение `AttributeError`). 
Если все-таки хочется добавлять новые поля, потребуется явно прописать `__dict__` в `__slots__`.

### 2. Weakref

Для weak references нужно отдельно добавлять `__weakref__` (иначе `weakref.ref(obj)` выбросит `TypeError`).

Стоит отметить, что некоторые кэши, observer-механизмы и библиотеки внутри используют weak refs, чтобы не удерживать объект от удаления. Без `__weakref__` это поведение недоступно.

### 3. Наследование

Наследование становится сложнее: в иерархии нужно аккуратно учитывать `__slots__` у базовых и дочерних классов.


**Вывод**: использовать `__slots__` следует при реальной необходимости (когда генерируется много однотипных инстансов, стремительно съедающих доступную память).


*ладно, не каждый — многие built-in/extension types не имеют обычного instance `__dict__` (например, `tuple`, `int`, некоторые типы из C-расширений); здесь имеются в виду экземпляры обычных пользовательских классов без `__slots__`

**допустима и строка (в случае одного имени)

***часто действительно немного ускоряет, но по факту зависит от версии Python и профиля нагрузки - выигрыш может быть и нулевым

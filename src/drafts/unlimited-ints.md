## Интро

В Python `int` не имеет фиксированного размера (в отличие от `int`/`long` в C, Java и т.п.), а поддерживает произвольную точность — числа могут расти до тех пор, пока хватает памяти.

## Как это устроено

Под капотом CPython хранит `int` не как машинное слово, а как массив «цифр» по 30 бит каждая (`PyLongObject`), то есть число разбивается на куски и хранится примерно как в школьной арифметике «в столбик», только по основанию 2³⁰, а не 10.

<div class="callout info">
<div class="ic">i</div>
<div class="body"><b>Идея</b><p>Число режется на «цифры» по 30 бит и складывается в массив <code>ob_digit</code>. Чем больше число — тем длиннее массив, а не шире машинное слово.</p></div>
</div>

Из этого следует:
- маленькие числа (влезающие в одну «цифру») считаются почти так же быстро, как в языках с фиксированным `int`
- большие числа требуют операций над массивом цифр — сложение/умножение больших чисел уже не O(1)
- потребление памяти растёт вместе с размером числа, а не фиксировано

```python/3
import sys

sys.getsizeof(0)          # 28 (служебные накладные расходы объекта)
sys.getsizeof(2 ** 1000)  # заметно больше — под цифры числа выделена память
```

## Подводные камни

### 1. Производительность на больших числах

Возведение в степень или умножение действительно больших чисел (тысячи/миллионы цифр) может быть неожиданно медленным — это уже не O(1), как для `int` фиксированного размера.

### 2. int → str на очень больших числах

<div class="callout warn">
<div class="ic">!</div>
<div class="body"><b>Грабли</b><p>Начиная с Python 3.11, конвертация огромных <code>int</code> в строку (и обратно) искусственно ограничена (<code>sys.set_int_max_str_digits</code>) — защита от DoS-уязвимости (CVE-2020-10735), когда <code>str(огромное_число)</code> могло положить процесс на минуты из-за квадратичной сложности конвертации.</p></div>
</div>

### 3. Кеширование мелких int

CPython кеширует небольшие целые числа (обычно от -5 до 256) — они всегда один и тот же объект в памяти, поэтому `is` может «внезапно» сработать как `==` для них. Для чисел за пределами этого диапазона так полагаться на `is` нельзя.

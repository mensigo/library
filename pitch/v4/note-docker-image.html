Образ и контейнер

3 мин14 октОбразыОсновы

Образ - неизменяемый шаблон, контейнер - запущенный из него процесс с тонким слоем для записи сверху. Из одного образа поднимаются десятки контейнеров, и диск почти не растет.

  • Образ. Набор read-only слоев и JSON с метаданными: команда запуска, env, пользователь.
  • Контейнер. Тот же образ плюс writable-слой и процесс в своих namespaces.
  • Следствие. Все, что записано в контейнер, умирает вместе с ним. Для данных есть volumes.

Образ #

Образ - неизменяемый шаблон: файловая система плюс метаданные. Физически это не один файл, а набор объектов, связанных хешами:

  • Слои - tar-архивы, в каждом только измененные файлы.
  • Config - JSON с метаданными: команда запуска, env, рабочая директория, пользователь, порядок слоев.
  • Manifest - оглавление: ссылка на config и список слоев с их размерами и хешами.

Имя каждого объекта - sha256 его содержимого. Поэтому два образа с одной базой физически делят одни и те же слои.

Контейнер #

Контейнер - запущенный экземпляр образа: те же read-only слои, тонкий writable-слой сверху и процесс в своих namespaces.

Dockerfile → docker build → образ → docker run → контейнер
Образ Контейнер
Можно писать нет да, в свой слой
Сколько штук один сколько угодно из одного образа
Когда исчезает docker rmi docker rm, вместе со всем записанным
Данные

Writable-слой удаляется вместе с контейнером. То, что должно его пережить - базу, загрузки, логи - кладут в volume.
